# トップページ ポータル型リデザイン 設計書

日付: 2026-07-06
ステータス: 承認済み（実装計画待ち）

## 目的

トップページを、提示されたデザインガイド付きモックアップに準拠したポータル型ニュースレイアウトへフル移行する。「毎朝2〜3分で重要ニュースを把握できる」情報密度の高い構成にする。

## 決定事項（ユーザー承認済み）

| 論点 | 決定 |
|---|---|
| 適用範囲 | フル移行（トップページ全体を再構成、モバイルもモック準拠） |
| アクセスランキング | 本物の閲覧計測を新規導入（Supabase テーブル追加） |
| 本日の重要ニュース | 自動選定（直近24時間の記事をスコア上位順に表示） |
| LINE CTA | 公式LINE友だち追加リンク `https://qr.paps.jp/KRwFx` |
| カテゴリ | 現行6分類を維持。「規制」の表示ラベルのみ「規制・政策」に変更（DB値は不変） |

## アプローチ

既存トップページ（`components/news-list.tsx`）の in-place 再構成。新ウィジェットは `components/` に個別コンポーネントとして追加。既存のティッカー・カード・データ層・フィルタ機構は流用する。別ページでの並行運用（フィーチャーフラグ）は、ベータ期でトラフィックが限定的なため採用しない。

## レイアウト設計

### ヘッダー（`components/site-header.tsx` 改修）
- 濃緑トップバー（タグライン・日付・ログイン・お問い合わせ）は現行維持（既にモック準拠）。
- メイン行を1段のコンパクト構成に整理: ロゴ＋ワードマーク（左）、カテゴリナビ（中央〜右）、検索ボックス（右）。

### 市況ティッカー（`components/market-ticker.tsx` スタイル調整）
- データ・更新機構（5分毎、`/api/market/snapshot`）は現行維持。
- 見た目をモックに合わせる: 緑の LIVE バッジ＋淡緑背景ストリップ。

### 本体グリッド
`max-w-7xl` 内で `lg:grid-cols-[minmax(0,1fr)_320px]`（メインカラム＋右サイドバー）。

### メインカラム
1. **ヒーロー**: 大カード1枚（画像＋大見出し＋要約＋日付）＋中カード4枚（2×2、画像＋カテゴリチップ＋日付＋見出し）。並び順は現行の人気スコア順の先頭5件。
2. **カテゴリ別ニュース**: カルーセル（`TopicCarousel`）を廃止し、縦リスト型ブロックに変更。6カテゴリを3カラム×2段で配置。各ブロック = カテゴリ見出し（アイコン/色付き）＋日付付きテキストリンク3〜4件＋「もっと見る」（`/?category=<key>`）。
3. **最新ニュース**: 表示日時の新しい順に6〜8件。サムネイル付き2カラムリスト（小画像＋カテゴリチップ＋見出し＋日時）＋「最新ニュースをもっと見る」ボタン。

### サイドバー（上から順、`lg:sticky`）
1. **本日の重要ニュース**（新規 `components/important-news-widget.tsx`）
   - 直近24時間の公開記事から `computePopularityScore` 上位3〜5件を自動選定（LLMの関連度スコアはDBに保存されていないため、既存の複合スコア＝新しさ・複数ソース・画像有無・要約充実度・featured を使用）。24時間以内の記事が3件未満なら最新記事で補完。
   - 表示: 公開時刻（JST HH:MM）＋カテゴリチップ＋見出し（記事へのリンク）＋「もっと見る」。
2. **アクセスランキング（24時間）**（新規 `components/access-ranking-widget.tsx`）
   - 番号 01〜05。直近24時間の実閲覧数順。閲覧データが5件に満たない場合は `computePopularityScore` 順で補完（導入直後も空にならない）。
3. **マーケット指標**（新規 `components/market-indicator-panel.tsx`）
   - `/api/market/snapshot` のデータを表形式で表示（銘柄名・値・前日比▲▼色分け）＋取得時刻＋「市況一覧を見る」→ `/?category=market`。
   - 既存 `MarketIndicatorWidget`（静的データ版）は置き換え。
4. **LINE CTA**（新規 `components/line-cta-box.tsx`）
   - 緑枠ボックス。「Go India 公式LINE 会員特典 — IndoBiz Japanの記事を無料で読める！」＋緑ボタン「LINEで友だち追加する」→ `https://qr.paps.jp/KRwFx`（外部リンク、新規タブ）＋「すでに友だちの方はログインしてください」→ `/login`。
   - URL は `lib/site-config.ts` に定数として置く。

- 現行の `CitySpotlightWidget` / `EditorialColumnWidget` / `TrendingWidget` はトップページから外す（コンポーネントファイルは残置）。コラムはカテゴリ別ニュースのブロックとして表示される。

### モバイル（1カラム、モック右端サンプル準拠）
ティッカー → ヒーロー → 本日の重要ニュース → アクセスランキング → カテゴリ別ニュース → 最新ニュース → LINE CTA。

## 閲覧計測（新規サブシステム）

### DB
- マイグレーション `supabase/migrations/0007_view_events.sql`
- テーブル `article_view_events`: `id uuid pk default gen_random_uuid()`, `article_id uuid references articles(id) on delete cascade`, `viewed_at timestamptz not null default now()`。
- インデックス: `(viewed_at)` および `(article_id, viewed_at)`。
- RLS 有効・クライアント直アクセスなし。書き込み/読み取りはサービスロール（API ルート／サーバーコンポーネント）経由のみ。
- 注意: 旧会員制で使われていた `article_views` とは別名。混同しない。

### 記録
- `POST /api/articles/[id]/view`（認証不要）: 記事本文ページ（`ArticleView`）のマウント時にクライアントから fire-and-forget で1件 insert。重複排除・bot除外はベータ期はしない（シンプル優先）。ティーザー表示（未ログイン）はカウントしない。
- 失敗してもユーザー体験に影響なし（エラーは握りつぶしてログのみ）。

### 集計
- トップページのサーバーコンポーネントで直近24時間の閲覧数を `article_id` ごとに集計し、公開記事と突合して上位5件を取得。
- 集計クエリの失敗時は人気スコア順にフォールバック（fail-open。ランキング枠は常に表示される）。

## 既存機能の維持

- カテゴリフィルタ・業界フィルタ・検索クエリ（`?category=` `?tag=` `?q=`）は現行動作を維持。フィルタ適用時は従来どおり検索結果ビュー（`FilteredResults`）へ切り替え、ポータルレイアウトは非表示。
- `usePublicArticles()` による published のみ表示、`ArticleStoreProvider` によるハイドレーションは不変。
- ダークモードは既存のデザイントークンで追従（ハードコード色は使わない）。
- 市況カテゴリ記事のスナップショット表示、記事ページ、admin は変更なし。

## エラーハンドリング方針

- 閲覧記録 API: 失敗しても throw しない。ランキング集計: 失敗時は人気スコアへフォールバック。
- マーケット指標: `/api/market/snapshot` 失敗時は「—」表示（ティッカーと同じ FALLBACK 挙動）。
- 各ウィジェットはデータ0件でもレイアウトを崩さない（枠ごと非表示 or 補完表示）。

## 検証

- `./node_modules/.bin/tsc --noEmit` を通す。
- `npm run dev` で実表示確認: デスクトップ／モバイル幅、フィルタ適用時、ダークモード、記事閲覧→ランキング反映。
- マイグレーションは Supabase に適用（ユーザー環境で実行）。

## スコープ外

- カテゴリ体系の変更（産業・企業／通信・IT の新設）
- 記事ページ・admin・パイプラインの変更
- bot 除外や重複排除つきの本格的アクセス解析
